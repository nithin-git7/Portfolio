The question

How can different kinds of business data become useful outputs in one application?

The approach

The project brings three model workflows together: Random Forest for churn prediction, DistilBERT for sentiment analysis, and CLIP for zero-shot image classification.

What was built

The documented deliverable is a unified dashboard combining predictive analytics, language, and vision.

  • Keras
  • scikit-learn
  • Streamlit

Read the project story

The question

How can several screening-model workflows share an interface while keeping their inputs and outputs distinct?

The approach

Random Forest and Logistic Regression handle diabetes and kidney-disease datasets. Convolutional neural networks handle image classification, with Streamlit connecting the workflows.

What was built

The documented application includes authentication, database support, and PDF reporting alongside its model workflows.

What needs careful evaluation

Tabular and image models need separate test sets and reports. The same patient or duplicate image should not appear in both training and evaluation data.

Current limits

This is an academic prototype, not a clinical diagnostic tool. Its results are not presented as evidence of clinical readiness.

From my notebook.

What should an AI forget?

I’m exploring selective memory: deciding what an agent should keep, recall, or release as its work changes.

The next step is an evaluation: compare selective memory with full-history and no-memory baselines, measuring useful recall and stale-information errors.

Selective memory demo

A small interactive concept, not a trained model.

Keep what will matter again.

“I am learning machine learning.”

A lasting goal can help with the next task. Keep it while it remains relevant.

Bring back what this task needs.

“Which topic should I study next?”

Recall the learning goal and the topics already covered, instead of loading every earlier conversation.

Release what is no longer reliable.

“The deadline I saved has changed.”

An outdated date should be replaced or flagged, rather than quietly influencing a new decision.

Questions behind the work.

Two short notes on how to examine an ML project.

A model score needs context

A score is useful only when the reader knows the task, the data, and how the test was set up. Churn prediction, sentiment analysis, and image classification need separate evaluation stories.

A useful report starts with a simple baseline, describes the held-out data, and shows the mistakes as well as the overall result. It also records the code and model version needed to repeat the test.

For these college projects, publishing that evidence is the next step. The portfolio does not repeat accuracy claims without the reports behind them.

More memory is not always more useful

Old context can be relevant, redundant, or wrong. A useful memory system needs to distinguish a lasting goal from a detail that has changed.

The selective-memory question here is whether a smaller, relevant memory can support a task without carrying forward stale facts. A fair experiment would give the same tasks to no-memory, full-history, and selective-memory baselines.

Useful recall, stale-fact errors, task completion, latency, and token use would be measured separately. This is a proposed experiment; the interactive example above does not run a memory model.
